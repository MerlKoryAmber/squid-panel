# CLAUDE.md — метод работы с ИИ-агентом (SPM)

Дистилляция метода работы с агентом. Лежит в корне репозитория; агент читает
как правила **выше** дефолтного поведения.

> Принцип №0: **эти правила выше привычек агента.** Конфликт с общим гайдом —
> репо побеждает, конфликт подсветить, не молчать.
>
> Конфликт со стилем Cursor по умолчанию (полные предложения): здесь побеждает
> **caveman** (§13), пока человек явно не снимет.

---

## 1. Роли не смешивать

Проектировщик ≠ строитель ≠ проверяющий ≠ приёмщик. Один участник — одна роль.
**Автор кода себе «принято» не ставит.** Минимум: read-only аудитор (ничего
не меняет) + исполнитель (себя не оценивает).

## 2. Пайплайн крупной задачи

`АУДИТ (чтение) → ПЛАН (согласовать до правок) → РЕАЛИЗАЦИЯ (ровно по плану) →
ВЕРИФИКАЦИЯ (другим, по фактам) → ПРИЁМКА ЧЕЛОВЕКОМ`. Шаги не пропускать.
Статусы: `НЕ НАЧАТА → В РАБОТЕ → РЕАЛИЗОВАНО НО НЕ ПРИНЯТО → ПРИНЯТО →
ЗАБЛОКИРОВАНО`. Делать ровно план — никаких «заодно, раз уж я здесь».

## 3. Доводить задачи до конца

Перед «готово» / сменой темы — сверка с **исходной формулировкой** попунктно.
Хвост назвать вслух и записать — **молчаливых хвостов нет**. Запрос с ≥2
пунктами — сразу в таск-лист. «Готово» только при пустом списке и после
верификации.

## 4. Верификация — независимыми, по фактам

После изменений, до «готово»:

1. **Код** — ревью качества/корректности.
2. **Безопасность** — fail-closed, RBAC, секреты, keytab/sudoers/spmd.
3. **Тесты** — покрытие нового/изменённого + регресс; гейт зелёный, если есть.
4. **UI глазами пользователя** (при выкатке UI) — живой сценарий от входа до
   результата. Поле под каждый нужный input. Пустота честная, не «чисто».

«Готово» без отчётов этих проверок не бывает. Приёмка — человеком.

## 5. Дисциплина изменений (данные, миграции, массовые правки)

`baseline → dry-run → регресс → apply с бэкапом → проверка после → точечный
коммит`. Без dry-run не менять. Бэкап до записи. Post-check — запросом к
данным до/после, не кодами ответа.

**SPM:** install и Save политики переписывают `/etc/squid/squid.conf` после
`squid -k parse`. Импорт в `spm.db` ≠ apply без parse. Live без parse не
трогать. Откат лабы: `squid.conf.spm-lab-baseline`.

## 6. Дисциплина коммитов и веток

- Коммит точечный, **явный список файлов; никогда `git add .`**.
- Код — ветки `feature/…`/`fix/…`; в `main` — слиянием по команде человека.
- **Порядок выкладки UI/кода:** (1) лаба — `scp` в `/opt/spm` (не `update.sh` без команды: сносит `spm.db`); (2) человек смотрит; (3) только потом **предложить git commit**; (4) **предложить push** ещё отдельным шагом, не в одном сообщении с коммитом. Не пушить «заодно».
- Force-push нельзя.
- Не коммитить секреты, `.env`, keytab, дампы, бинарные артефакты.

Коммит — только если человек явно попросил (это же репо + правило владельца).

## 7. Не терять коммиты — всё доходит до main

Работа из веток доходит до `main` по правилам либо **явно списана**. Не
`git stash pop` слепо. Не `git add .`.

## 8. Параллельные сессии — всегда предполагать

Перед правками: сверка состояния. Общие номера (версия, ADR, миграции) не
занимать «у себя» молча.

## 9. Конфликт разрешает ИИ, а не человек

Конфликт — ветка `reconcile/<задача>`, `main` не трогать, результат —
**предложение**. Две живые реализации одного поведения — не дефолт. Провал
объединения → **ЗАБЛОКИРОВАНО**.

## 10. Документы важнее памяти

Решения — в файлах репо. Сначала docs, потом чат. ADR: `docs/adr/`. Не
записано — решения нет. После изменений до «готово»: CHANGELOG/README/handoff
по факту. Результаты выкладки — в документацию.

## 11. Отчёты и промпты

Один промпт — один шаг. Полный отчёт — `docs/agent_reports/<задача>/REPORT.md`,
в чат — 5–8 строк.

## 12. Субагенты — когда необходимо

Не раздувать простые правки. Верификация не автором (§4), широкий аудит,
параллельные независимые ветки — да. Агент субагентов сам не «принимает».

## 13. Стиль ответов и коммитов

- **Ответы — caveman**: по делу, вода убрана. Код, команды, имена, ошибки —
  дословно. Снимается явной командой.
- **Коммиты — caveman-commit**: Conventional Commits, тип латиницей, текст
  после двоеточия по-русски; точечно, явный список файлов.
- Предупреждения безопасности и необратимое — обычным языком, без сжатия.

## 14. Скиллы — читать перед задачей, когда применимы

Даже малый шанс, что скилл применим — прочитать до первого действия. Чек-лист
скилла — в задачи. Этот `CLAUDE.md` и указания владельца выше скилла.

## 15. Вопросы — только формой с вариантами и пояснениями

Вопрос человеку — варианты + последствия у каждого; рекомендуемый первым.
Не прозой, даже «да/нет». Проза — только статус без вопроса.

## 16. Не придумывать — искать и переиспользовать

Сначала код и доки этого репо. Штатное Squid/PHP/systemd предпочтительнее
самописного. Не уверен — спросить формой, не гадать.

## 17. Локальные операции без переспрашивания

Не спрашивать на локальные обратимые: fetch, локальные тесты, установка
зависимостей. Push, деплой, удаление данных, отправка наружу — с
подтверждением.

## 18. Убирать за собой диск

Свои temp/архивы/логи — удалять. Пользовательские файлы и данные проекта не
трогать. Живой Squid и `/etc/squid` — не «уборка».

## 19. Приёмка и документация — после

«Принято» ставит **только человек**. После принятого внедрения — ADR/README и
дублирование в память агента. Ниже ПРИНЯТО итог в доки не фиксировать.

## 20. Время — всегда МСК

Ответы/отчёты/ADR/имена файлов — МСК (UTC+3). Чужой источник — перевести и
подписать зону: `14:20 МСК (11:20 UTC)`.

## Грабли

- Сырые числа, не вердикт PASS.
- Пустое поле ≠ «чисто».
- Дробить сессии к ~40–60% контекста.
- Диагностика: данные → API → рендер → разметка → стили → редизайн.
- Проверка, которая не может провалиться — не проверка.
- Гипотеза ≠ факт; grep по истории до своего фикса.
- Baseline сверять живым состоянием перед действием.
- Капчу и серые защиты не обходить.

## (проект) SPM

- **Handoff (читать первым):** `docs/agent_reports/handoff/2026-08-23.md`
- **Владелец:** Merl. Стек: PHP-панель + `spmd` (Python), SQLite `spm.db`,
  Squid на CentOS 9 / Rocky 9, nginx :8443, PHP-FPM `squidmgr`.
- **Не трогать без команды:** рестарт Squid (`systemctl restart`), push,
  force-push, `git add .`. Live `squid.conf` — только через parse+apply/install.
- **Выкладка UI:** `scp` в `/opt/spm` → смотрит человек → предложить commit →
  отдельно предложить push. `/opt/update.sh` — только явно (клонирует GitHub,
  сносит `spm.db`, формат live conf).
- **Секреты:** keytab только `/etc/squid/*.keytab`, sudoers точные пути,
  пароли/`.env`/дампы не в git.
- **Политика на Squid:** Save ACL / HTTP Access / Cascade / Listen → полный
  `squid.conf` (auth + extra + coredump), backup `*.spm-policy-*`, parse, reconfigure.
- **Каскад:** пиры по `name=`; большие списки сайтов — файл
  `/etc/squid/acl.d/<acl>.txt`, не JSON на тысячи строк.
- **ADR:** `docs/adr/README.md`. Отчёты агента: `docs/agent_reports/`.
- **Горячие пути:** импорт `SquidConfigParser` (CLI обязан грузить сервисы),
  `PrivilegedExecutor`/`spmd`, статус Squid через `/proc` + `is-active`.
