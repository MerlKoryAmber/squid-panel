# План: простой UI политики (ADR 0003)

Дата: 2026-08-20, 19:55 МСК.  
Статус: **согласован** (человек, 2026-08-20, 19:55 МСК). Код — по этому плану.  
База: ADR 0003 ПРИНЯТО. Живой `squid.conf` целиком не трогать.

## Цель

Переключатель **Эксперт / Простой** на тех же таблицах. Простой язык: откуда/куда/действие и кто→канал. Слово ACL нет в простых HTTP rules и простом каскаде.

## Вне скоупа

- Вторые таблицы `*_simple`.
- Переписывание live conf генератором.
- Смена импорта `SquidConfigParser` по смыслу (только классификация «простое vs сложное»).
- Полноценное «кроме списка» (`!acl`) в простом UI.
- Редизайн ACL-страницы (можно позже подпись «Списки»).

## 0. Режим UI

- Колонка `users.policy_ui` TEXT `simple`|`expert`, default **`expert`** (импорт live не пугает).
- `addColumnIfMissing` как остальные миграции панели. Сессия читает из user, POST переключателя пишет в user + `$_SESSION`.
- Шапка: сегмент «Простой | Эксперт» на `/http_access` и `/peers` (и общий в layout — ок).
- Operator/admin: оба видят переключатель; сохранение правил — как сейчас по роли.

## 1. Классификатор ACL (сервис, без UI-слов)

Файл вроде `app/Services/PolicyAclKind.php`.

| kind | Squid `acls.type` (и имя) |
|------|---------------------------|
| from | `src`, `srcdomain`, `srcdom_regex`, `arp`, `proxy_auth`, `ext_user`; ACL `ad_*` / type `external` helper групп |
| to   | `dstdomain`, `dstdom_regex`, `dst`, `url_regex`, `urlpath_regex`; `storage=file` списки сайтов |
| other| `port`, `myport`, `method`, `proto`, `browser`, `time`, `rep_mime_type`, `CONNECT` как method, прочее |

Правило **простое**, если все токены (без `!`) — только from и/или to, хотя бы один токен. Иначе **сложное**.

Пустой «откуда» в простом UI = любой источник (не писать фейковый `all`, если `all` нет в БД). Пустой «куда» = любой dest. Оба пустые — запрет в форме.

## 2. HTTP rules — простой вид

Те же URL `/http_access` (не плодить маршруты без нужды). `HttpAccessController`: ветка по `policy_ui`.

**Список:** колонки Откуда | Куда | Действие | (описание опционально). Drag как сейчас. Без preview `http_access`, без колонки ACLs, без бейджей имён Squid. Сложные строки: текст «Сложное правило» + кнопка в эксперт (или только иконка).

**Создание/правка:** два мультиселекта (подписи «Откуда», «Куда»), списки из ACL kind from/to, действие разрешить/запретить. Сохранение: JSON `acls` как сейчас, порядок from затем to. Не умеет править сложное — редирект в эксперт.

Эксперт: текущий `index`/`edit` без изменений смысла.

## 3. Каскад — простой вид

Пиры слева **оставить** (создание канала: имя, host, порт) — это не «ACL». Справа и снизу в простом виде **одна** таблица маршрутов, не peer-access + «When to use cascade».

**Строка маршрута:** Откуда | Куда | Канал (`peer_id` или Direct). Drag. First match.

**Компилятор** `app/Services/CascadeRouteCompiler.php` (имя рабочее):

Вход: логические маршруты. Пока **не** новая таблица, если можно стабильно восстановить из существующих строк. Если восстановление неоднозначно (импорт) — тогда узкая таблица `cascade_routes` (from_acls, to_acls, channel, sort_order) как **проекция**, при save simple пересобирает Squid-таблицы. Рекомендация плана: **проекция `cascade_routes`**, потому что `cache_peer_access` + `routing_rules` неоднозначно читаются обратно.

Save простого каскада (транзакция):

1. Удалить сгенерированные `cache_peer_access_rules` и затронутые `routing_rules` этой проекции (маркер в description/`acl_entries` или полное пересобрать routing+access из проекции — **полное пересобрать из `cascade_routes`**, эксперт после этого видит результат компиляции).
2. Для канала пир X: `cache_peer_access` allow на X с токенами from+to; deny те же токены на каждом другом active peer; `never_direct allow` те же токены.
3. Для Direct: `always_direct allow` те же токены; не добавлять peer allow.

Конфликт: эксперт правил access вручную, потом save в простом — **перезапишет** access/routing из проекции. В простом UI предупреждение один раз. Эксперт остаётся источником, если проекция пуста (только импорт) — простой показывает сложное/только пиры.

`lock_path` / «Forbid DIRECT» в простом UI нет.

## 4. Копирайты UI

Простой HTTP/каскад: запрещены строки ACL, `http_access`, `never_direct`, `cache_peer_access` в видимом тексте. Код/комменты/эксперт — можно.

## 5. Тесты / проверка

- Классификатор: фикстуры типов + `!name` → сложное.
- HTTP simple store → JSON acls в БД как эксперт ожидает.
- Компилятор: 2 пира + маршрут на A + маршрут Direct → ожидаемые строки access/routing.
- Регресс экспертных view: не ломать POST существующих форм.
- UI глазами: simple list без слова ACL; переключатель туда-сюда; сложное правило с импорта.

Гейт PHP: если в репо нет автотестов — минимум php `-l` + ручной сценарий в `docs/agent_reports/dual-ui-kwts/REPORT.md` после реализации (отчёт пишет не «я принял»).

## Порядок работ (после согласования плана)

1. Миграция `policy_ui` + переключатель + layout.  
2. Классификатор + простой HTTP list/edit.  
3. Таблица проекции + компилятор + простой каскад.  
4. Сложные/импорт в UI.  
5. Верификация другим, не автором.  
6. Приёмка человеком. Коммит/push — только по команде.

## Риски

- Полный rebuild access из проекции затирает ручной экспертный каскад — явно в UI.  
- Нет `all` в БД — пустой from/to = «любой» без токена; Squid `http_access allow` без ACL = allow всем — **нельзя**. Пустой набор: не emit голый allow; требовать хотя бы from или to; «любой» = существующий ACL `all` если импортирован, иначе блок «нужен список» / создать системный `all` src только через эксперт/импорт, не молча.
